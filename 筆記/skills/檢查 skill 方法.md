# Skill 檢查指南：可讀性、流程、規則與維護性

拿到 AI 撰寫或修改的 Skill 時，可以從可讀性、流程、規則與維護性檢查，確認自己能理解它如何運作，也知道需要調整時該改哪裡。適合在第一次審閱或流程調整後使用。

## 先看用途與主流程

- [ ] 看得出 Skill 解決什麼問題、何時使用。
- [ ] 找得到明確的主流程，能順著讀出執行順序。
- [ ] 能區分流程、規則與概要，不會因三者交錯而看不出下一步。
- [ ] 每個步驟交代清楚要讀什麼、生成什麼或執行什麼。
- [ ] SOP 中沒有夾入打斷流程、重複說明的大摘要或小提示。

「流程、規則、概要」是原筆記用來檢查文字的分類角度；檔案如何分工，另見 [Skill 模組化](./Skill%20模組化.md)。

## 用五個設計約束檢查

![Skill 設計的五個約束：按需載入、遵守流程、遵守規則、執行效率與規則單一溯源](./檢查%20skill%20方法-assets/image.png)

| 檢查面向 | 檢查問題 |
| --- | --- |
| 按需載入 | 是否在需要的步驟才讀取相關規則與樣板？ |
| 遵守流程 | 階段、步驟順序與分支是否清楚，能否看出何時進入下一步？ |
| 遵守規則 | 各步驟是否指出應遵守哪些規則？ |
| 步驟執行效率 | 是否有適合透過腳本加速的步驟？已有腳本時，是否交代何時執行？ |
| 規則單一溯源 | 同一條規則是否只在一處定義，避免多份文件重述後不一致？ |

這些是本課程的設計與審閱方向。課程提到可搭配任務管理工具提高遵循步驟的可靠度，但本單元尚未提供具體操作；文件結構本身並不保證 AI 一定不跳步驟。

## 再看是否容易維護

- [ ] 要改某條規則時，能直接找到定義位置。
- [ ] 流程、條列規則、生成樣板與腳本的職責清楚。
- [ ] 複雜步驟若已形成另一套流程，能判斷是否需要抽成另一個 Skill。
- [ ] 自己能解釋 Skill 的運作，也敢修改其中的內容。

修改流程時參考 [Skill SOP 寫法](./Skill%20SOP%20寫法.md)；拆分時機參考 [Skill 漸進式演化](./Skill%20漸進式演化.md)。

## 原筆記的提醒

讀不懂 AI 寫的 Skill 時，先檢查是否是描述或組織不清楚，不要直接認定是自己認知不足。Skill 雖然交由 AI 執行，人也需要讀得懂，才能審閱與維護。
