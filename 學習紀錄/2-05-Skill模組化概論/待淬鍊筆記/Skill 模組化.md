# Skill 模組化：SOP、rules、templates 與 scripts 的分工

本課程以主流程作為 Skill 的骨架：由 SOP 串起階段與步驟，再由各步驟按需載入規則、參考樣板或執行腳本，讓 Skill 容易理解、執行與維護。

當 Skill 的細節逐漸增加，需要分清楚「流程放哪裡、規則改哪裡」時，可以用這個結構整理。

## 各部位的職責

![模組化 Skill 總覽：SKILL.md 放流程，各步驟按需使用 rules、templates 與 scripts](../../../筆記/assets/c2m5-0/檢查%20skill%20方法-assets/image%207.png)

| 部位 | 職責 | 使用方式 |
| --- | --- | --- |
| `SKILL.md` | 主流程，包括階段與步驟。 | 指出每一步做什麼，以及何時使用其他資源。 |
| `rules/` | 條列式規則，說明步驟執行時應遵守的要求。 | 由相關步驟指定讀取；課程建議規則附上好的與壞的示範。 |
| `templates/` | 生成產物的格式與樣板，說明產物應包含什麼內容。 | 在生成對應產物時參考。 |
| `scripts/` | 可執行的腳本，用來加速或提高步驟的準確度。 | 由需要的步驟指定執行。 |

課程將衍生規則分成「條列式規則」與「格式／樣板」。前者約束如何執行，後者提供生成產物的參考。

## 流程如何連到資源

主流程可以包含多個階段，每個階段再拆成步驟。規則與腳本可對應到較大的階段，也可對應到個別子步驟，依需求指定使用時機。

例如，繪製類別圖時，相關步驟可以讀取類別顆粒度規則、參考 Mermaid 樣板，並執行程式類別靜態分析腳本。完整案例見 [Skill 漸進式演化](./Skill%20漸進式演化.md)。

## 這個結構要解決什麼問題

- **Context 管理**：資源按需載入，避免所有細節一開始都進入 Context。
- **執行可靠度**：主流程交代順序，各步驟指出相關規則，減少跳步驟或漏規則的機會。
- **執行效率**：適合程式處理的步驟可抽成腳本。
- **維護性**：每條規則只有一個定義來源，修改時不用同步多份重複敘述。

「單一溯源」指同一條規則只在一處定義；需要它的步驟引用該處，不在不同檔案重新包裝或詮釋同一條規則。

## 設計範圍

這是講師在 Skill 套件結構上採用的組織方法。講師偏好直接使用 `rules/`、`templates/` 等用途明確的名稱，省去較籠統的 `assets/` 或 `references/` 層；這項命名選擇不應寫成所有 Skill 的通用禁令。

初期不需要建立全部資源目錄。先有簡單 SOP，再隨需求抽出細節。
