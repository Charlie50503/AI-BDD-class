# SOP 格式規範

本檔為 SOP section 的格式條文。撰寫流程見 [SKILL.md](../SKILL.md) 的 `# SOP`；
該 section 本身即依本規範寫成，可作為唯一的標準範例。

## 1. 結構

- SOP section 的標題固定為 `# SOP`。
- 其下為 3 至 5 個 Phase，標題格式為 `## Phase N — <名詞式標題>`，N 由 1 起連續編號。
- 每個 Phase 的內容依序為：編號步驟（1. 2. 3. ...），再加一行以「出口條件：」起始的句子。
- Phase 之間為嚴格順序，不得跳躍或並行。

## 2. Phase 標題

- 使用名詞短語，描述「這一階段結束後桌上多了什麼」，而非「這一階段在做什麼」。
  - 可：`階段切分`、`流程邊界清單`
  - 不可：`開始切分階段`、`進行需求分析`
- 標題須能單獨回答「做完這段，我手上多了什麼」。
- 若相鄰兩個 Phase 之間不存在可被檢查的中間產物，合併為一個 Phase。

## 3. 步驟與動詞表

每一步以單一動詞開頭，動詞為下列封閉集合之一，後接該步驟的具體行為描述：

| 動詞 | 意義 |
| --- | --- |
| `READ` | 讀取檔案或既有內容 |
| `WRITE` | 寫入或修改檔案 |
| `THINK` | 進入 extended thinking 進行判斷 |
| `DELEGATE` | 將此步職責交付給 script 或其他 skill |

- 動詞後所接者必須是可被觀察的動作。「確保」「注意」「保持一致」等非動作語句，
  應刪除或改寫為上述四個動詞之一。
- 寫不進動詞表的內容，代表它不是流程步驟（多為原則或提醒），應移出 SOP section。

## 4. 出口條件

- 每個 Phase 結尾恰有一行「出口條件：」。
- 內容描述「用什麼跡象判定本階段已完成」，須為可被指認的具體物件或可判定的事實
  （檔案、段落、回覆、數量），不得為「理解需求」「準備就緒」這類心理狀態。

## 5. 檢核清單

交付前逐條比對，全數通過方可寫入目標 SKILL.md：

- [ ] 存在 `# SOP` 標題。
- [ ] Phase 數量介於 3 至 5，編號連續。
- [ ] 每個 Phase 標題為名詞短語。
- [ ] 每一步皆以 `READ` / `WRITE` / `THINK` / `DELEGATE` 之一開頭。
- [ ] 每個 Phase 恰有一行「出口條件：」。
- [ ] 每項出口條件皆指向具體物件或可判定的事實。
- [ ] 不具本次對話脈絡的人，可只憑此 SOP 執行到底。
